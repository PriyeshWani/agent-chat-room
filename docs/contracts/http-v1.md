# HTTP composition seams, local v1

Design interfaces for H2 packets; behavior must be tested by their owners. Existing wire shapes/errors remain authoritative in local-v1. Every factory receives existing repository/service instances; handlers never recreate storage or duplicate business rules.

## H2.1 shell

`async createHttpServer({port=0,host='127.0.0.1',handlers=[],assets,onError}={})` in http-server.js returns `{server,url,close}` after listening. Reject hosts other than `127.0.0.1` in this local release. Port is an integer 0–65535; 0 asks OS for a free port. The actual port determines allowed Host/Origin values, default exactly `127.0.0.1:<port>` and `http://127.0.0.1:<port>`.

A handler gets `{request,response,url,path,method,body,signal}` with `url` a parsed URL and `path` its pathname (including `/api/v1`). It returns undefined if unmatched, `{data,schema,status?}` for a shared output schema, or `{handled:true}` when it owns a stream/response. Dispatch sequentially until matched. No route registration in packet H2.1. Built-in health GET /api/v1/health returns Outputs.health. All other API requests default to structured NOT_FOUND. `assets` is an optional same-shape handler for non-API requests.

Shell duties:

- Validate Host before responding. Reject any present Origin other than the exact page origin. No wildcard CORS or OPTIONS permission response.
- For mutations, require application/json, enforce LIMITS.bodyBytes while reading (including chunked bodies), parse once, and reject malformed JSON. Browser bootstrap requires matching Origin. Other mutations with no Authorization also require Origin, except POST /api/v1/sessions/agent (local enrollment). Authentication services still validate any bearer; the header alone does not grant access.
- Methods supported by individual routes are exact. Unknown paths/methods produce NOT_FOUND, not a false successful mutation.
- Validate handler data through Outputs[schema]; schema-invalid *output* is INTERNAL_ERROR 500, never a user validation error. Convert thrown Zod input errors to safe VALIDATION_ERROR 400 and typed ApiError to its declared envelope/status; unknown errors give generic INTERNAL_ERROR 500. `onError` may receive unknown errors for local logging, without echoing them to clients.
- Abort the per-request signal on request abort, premature response close, or hub close. Long receives/SSE must attach cleanup to this signal. Do not abort a live stream just because the incoming GET body has ended.
- Close is idempotent, cancels all requests, closes listening/idle sockets, and bounds remaining socket teardown. Clean response listeners/request bookkeeping at completion. No browser/MCP child management here.

`createStaticAssets()` in static-assets.js returns a handler. Map exact paths `/` and `/index.html` to public/chatroom/index.html; `/<name>` to explicitly allowlisted chatroom modules/css (index,style,theme,rooms,drafts,conversation,composer,mentions,event-feed,participants,app). `/shared/client.js` and `/shared/protocol.js` map to those two portable source modules. No directory listing, arbitrary file joins, private data, fixture or node_modules routes. Serve only GET/HEAD with correct HTML/CSS/JS MIME, nosniff, and conservative cache policy. Missing not-yet-created assets return NOT_FOUND. Do not treat filesystem errors as permission to serve another path. Test the app's path allowlist with ordinary local requests; do not probe environment controls.

H2.1 writable files: src/hub/http-server.js, src/hub/static-assets.js, test/hub-h2-1.test.js. Verify loopback readiness/free port, health, static MIME/HEAD/allowlist, Host/Origin/JSON/body limits, malformed output/error hygiene, abort propagation and bounded close. This packet has no authentication repositories or room route registration.

## Later packets: shared route conventions

Factories below return one handler matching the shell's dispatch convention. They are registered only by H2.7. `sessions.authenticate(request)` resolves internal context. It is synchronous and uses identity's credential checks. Business methods revalidate context inside transactions.

- H2.2 `createLocalSession({identity,presence?,changes?})` returns `authenticate(request)`, `browserSession()`, `agentSession(input)`, `heartbeat(context,input)`, `disconnect(context)`. It parses Bearer/cookie headers (ambiguous/duplicate credentials fail) and delegates durable binding. `browserSession` preserves the private token for its route to set the cookie. Optional presence receives touch on valid authentication/enrollment/heartbeat and disconnect after durable disconnect; no durable presence inference. Emit optional changes event `identity` with participant ID after successful enrollment/resume/disconnect so active streams/waits revalidate. `createSessionRoutes({sessions})` registers exact wire session paths through a returned handler. No circular dependency: presence is injected through a facade by composition. Browser route sets acr_session cookie and returns only {participant}; exact header attributes are in local-v1. Parse Inputs.browserSession/agentSession/heartbeat and strict empty disconnect body; no private state in route responses except declared agent enrollment bearer.
- H2.3 `createRoomRoutes({sessions,rooms,events,onChange})` and `createMessageRoutes({sessions,events})`. Room routes authenticate and delegate list/create/join/leave/history; join assembles bounded history through the captured join head. `onChange(roomId)` after successful join/leave wakes services to recheck membership. Message route delegates events.post. Query numbers must be strictly validated; no silently parsing `1oops` or duplicate parameters.
- H2.4 `createDeliveryService({delivery,rooms,identity,changes})` returns `receive(context,roomId,input,{signal})`, `ack(context,roomId,input)`, `isReceiving(participantId,roomId)`, `close()`. `changes` is a Node EventEmitter; event `room` supplies roomId, event `identity` supplies participantId. Receives subscribe and recheck durable state without a lost-wakeup window, own one waiter per membership epoch, and clean up on timeout/abort/leave/replacement/shutdown. `createDeliveryRoutes({sessions,deliveryService})` matches /receive and /ack.
- H2.5 `createPresenceService({identity,rooms,events,deliveryService,now=Date.now,ttlMs=30000})` returns `touch(context,input={})`, `disconnect(context)`, `list(context,roomId)`, `close()`. Read-only lists use active room members and revalidate stored connection generations; restart has no in-memory presence. Reported activity retains its timestamp only within TTL; stale fields become null. Pending count is raw head minus acknowledged progress for agents, zero for humans. Connection/delivery/activity are independent. `createPresenceRoutes({sessions,presence})` matches participants.
- H2.6 `createBrowserStream({events,rooms,identity,changes,heartbeatMs=15000})` returns `stream(context,roomId,after,{response,signal})`, `close()`. SSE replay is durable and room-scoped; assert context and epoch at replay/wakeup. End streams on leave/replacement, bound slow consumers, clear timers/listeners. `createStreamRoutes({sessions,browserStream})` matches stream and validates after. Return handled:true while the stream remains owned until abort/close.

Actual event/delivery methods are specified in events-v1.md. No worker implements an unavailable dependency.

## H2.7 composition

`async createHub({filename,port=0,host='127.0.0.1',bootId=crypto.randomUUID()})` in src/hub/main.js returns `{url,close}` using the actual component factories. `filename` is required (test files may use :memory:). Construct database, identity, rooms, events, durable delivery, receive service, presence, browser streams, sessions and HTTP routes in dependency order. A shared EventEmitter supplies room/identity change hints. Session construction can follow presence, so no circular injection is needed. No production fixtures.

`createRoutes({sessions,rooms,events,deliveryService,presence,browserStream,changes})` in routes/index.js returns the six existing route handlers (session, rooms, messages, delivery, presence, stream) for the shell. Room/event mutations emit room hints after their commits. Use createStaticAssets for the UI and shared modules.

close() is idempotent and cancels HTTP requests/waits/streams, stops presence, awaits bounded HTTP close, then closes SQLite and listeners. Construction errors must close already-owned resources. Do not duplicate business logic or change packet-owned components here; report defects to coordinator for a scoped fix.

scripts/hub.js reads the exact ROOM_HUB_PORT/DATA environment contract in adapter-v1.md, prints one readiness line, and owns SIGINT/SIGTERM handling. Exported main.js remains import-safe. H2.7 writes src/hub/main.js, src/hub/routes/index.js, scripts/hub.js, test/hub-h2-7.test.js. Tests exercise a real hub process with shared browser/client helpers: bootstrap, create/join/post, receive/ack, SSE and clean shutdown/restart. No authenticated model process. Package scripts belong to the coordinator.
