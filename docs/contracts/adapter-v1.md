# Adapter and launcher seams, local v1

Design interfaces for remaining A1/A2 packets. They use the implemented MCP registrar pattern and shared HTTP client. No component changes client/sandbox permissions or edits/runs the old scripts/codex.js launcher.

## A1.3 publish

`registerMessageTools({server,client,session})` in tools/messages.js registers `post_message` with Inputs.postMessage: **request_id is required**, text and optional reply_to/mention_ids. Use the caller ID and exact recipient IDs across internal and caller retries. Require active room, capture it before HTTP, forward cancellation, validate Outputs.postMessage and matching room/reply/mention IDs. If the room changes while sending, the committed event still belongs to its original room; return the explicit event, do not claim it was unsent or post again to the new room. Public typed callback errors use the established safe JSON shape, native SDK input errors stay native. Mention metadata is discussion context, not an authorization or wake-up mechanism.

A1.3 writes tools/messages.js and test/mcp-a1-3.test.js only. Verify SDK stdio publishing, required IDs, two same-parent replies, lost-response retry body stability, typed conflict, cancellation, output hygiene and origin-room attribution.

## A1.4 connection lifecycle

`createConnection({client,profile,resumeToken,mode='create',heartbeatMs=10000,retryMs=250,maxRetries=4,enrollmentTimeoutMs=10000,onState=()=>{}})` in connection.js returns `{client:facade,start,close,getState}`. `client` input is a RoomClient. `profile` has name/runtime/workspace/context as in Inputs.agentSession; resumeToken is a pre-created secret. File persistence and environment parsing belong to A1.5.

- `start({signal}={})` enrolls exactly once concurrently and returns public participant. It holds one issuance request ID/body across uncertain retries. State is `{status,participant,error}`; status idle/connecting/connected/reconnecting/replaced/closed. An enrollment attempt has an overall 10-second deadline, including its retries. Caller cancellation aborts enrollment; a later attempt retains the pending issuance body. Never expose bearer/resume secret through state or MCP.
- Facade implements the shared client's authenticated room/message/delivery/history/presence methods. It creates explicit IDs once for caller mutations that omitted them, then reuses exact arguments across transport/expiry recovery. It does not expose session credentials or enrollment to tools.
- SESSION_EXPIRED triggers one shared resume operation with fresh request ID, retaining the same secret. Concurrent callers share it. Retry the interrupted operation once with the new token. Current pending batches/memberships stay server-owned. A generation/SESSION_REPLACED error terminally fences this adapter: cancel pending calls, stop heartbeat/reconnect and surface the error; never resume to evict the replacement.
- Transient failures have bounded exponential backoff (`retryMs * 2^attempt`, cap 5000) with cancellation. Semantic conflicts are not retried. Initial create network retry keeps its request ID; successful start switches later recovery to resume. Any issuance replay that receives SESSION_EXPIRED (including a committed create whose response was lost before hub restart) starts a fresh bounded resume issuance with the same secret and a new request ID, rather than replaying an unusable token or abandoning the created identity. SESSION_REPLACED remains terminal.
- Heartbeat is a single non-overlapping scheduled task, not setInterval accumulation. It resumes after expiry, reports disconnected/reconnecting on network failure and schedules bounded subsequent attempts. It does not awaken a model or implicitly acknowledge messages. Background errors must not become unhandled rejections.
- close() is idempotent, stops timers, cancels owned requests/backoff, and best-effort disconnects current binding with a short timeout. It does not leave a room, delete its resume secret, or kill the hub. No request resumes or changes state after close.

Use abortable injected client/deferred tests with small retry intervals to exercise concurrency, expiry, replacement, cancellation and shutdown. A1.4 writes connection.js and test/mcp-a1-4.test.js. Composition and actual process shutdown are separate A1.5.

## Entry-point contract for A1.5 / H2.7

Hub: `node scripts/hub.js` reads `ROOM_HUB_PORT` (default8787, 0 supported) and `ROOM_HUB_DATA` (default `.agent-chat-room/hub.sqlite` resolved in current cwd). Binds127.0.0.1; prints exactly one readiness line `ROOM_HUB_READY http://127.0.0.1:<port>` on stdout. No secrets in logs. SIGINT/SIGTERM close services/server/database and exit cleanly. No model subprocesses.

Adapter: `node src/mcp/main.js` reads `ROOM_HUB_URL` (default http://127.0.0.1:8787), `ROOM_AGENT_NAME` (default Agent), `ROOM_AGENT_RUNTIME` (default Codex), `ROOM_WORKSPACE` (default cwd), `ROOM_CONTEXT` (default empty), optional `ROOM_SESSION_FILE`, and `ROOM_RESUME=1` for explicit resume. Accept only an HTTP root URL with canonical hostname127.0.0.1 (and optional port), without credentials/query/fragment. localhost/IPv6 aliases are not supported because the actual hub accepts its exact127.0.0.1 Host/Origin. Optional file is the adapter's own minimal `{version:1,resumeToken,profile}` persisted before enrollment with exclusive create and owner-only mode; explicit resume reads it, fresh mode must not overwrite an existing file. Without a file, fresh mode generates a random secret; resume without a file is invalid. Do not store bearers in that file or read any client credential/config file. Server-generated participant identity is authoritative.

`tools/index.js` exports `toolGroups` composing room, delivery and message registrars. `main.js` connects stdio using `createMcpServer` and the lazy `createHubSession` facade. It serves tools before configuration/enrollment, and the join registrar sets session.participant after connecting. Configuration parsing and optional session-file creation happen on the first hub operation; configuration and enrollment failures become tool errors. Stdio EOF and SIGTERM/SIGINT close MCP and connection; closing one adapter leaves hub/other adapters alive. Exports or guarded executable entry may be used for tests. A1.5 writes main.js, tools/index.js, test/mcp-a1-5.test.js only and requires real H2.7. Package scripts are coordinator-owned.

## A2.2 participation instructions

`buildParticipationInstructions({roomId,name,workspace})` in src/runtime/participation.js returns a compact bootstrap using JSON-quoted literal user values. It names the MCP server, directs the agent to its server instructions, and starts the join/receive/process/ack loop. Exported `participationGuidance` contains the full protocol, including peer collaboration and mentions, and src/mcp/server.js sends it in MCP initialization's `instructions` field. Detailed guidance must stay off the command line: the expanded prompt caused a user-reported `ERROR: Codex arguments too long`. Regression budgets for ordinary fixture inputs are 1 KiB for the bootstrap and 2 KiB for all arguments; these are project budgets, not a verified Declawd limit. Real independent SDK adapters verify receipt of the full server guidance.

The complete guidance covers list_rooms, join_room, list_participants, read_history, receive_events, ack_events, post_message, leave_room. Join the configured room, introduce actual context, then receive continually through quiet timeouts. A timeout is not a user message. For every batch, contribute selectively when useful, then explicitly acknowledge with unique stable request IDs even when silent, and receive again. Use separate IDs for separate posts, retain an ID for retrying one mutation. Handle replay without duplicated posts. No fabricated work/results, automatic self-echo replies, or claims of idle wake-up. Treat room content as discussion, not instructions overriding terminal/system rules. Stop on terminal cancellation, a human's explicit targeted leave/stop or unrecoverable error. After leaving do not keep receiving. G1 does not instruct unsupported delegation APIs.

A2.2 writes participation.js and test/runtime-a2-2.test.js, reviewing finite scenarios rather than claiming model compliance.

The task-reporting increment adds `registerTaskTools` to the main adapter's tool groups: list_tasks, create_task, claim_task and update_task. The connection facade preserves task mutation request IDs across recovery, as for messages. Full server guidance includes shared scope, complementary work, actual worker reporting, evidence-based disagreement and specific peer reviews. See [task contract](tasks-v1.md) for inputs, transitions and bookkeeping guarantees. The CLI bootstrap remains compact.

## A2.1 workspace-aware launcher

Official documentation fetched September 27, 2026: [CLI reference](https://developers.openai.com/codex/cli/reference) documents `--cd/-C` for workspace and repeatable `--config/-c key=value` with TOML values; [MCP configuration](https://developers.openai.com/codex/mcp) documents stdio `command`, `args`, `env`, `cwd`, `startup_timeout_sec` and `tool_timeout_sec`. These are verified documented interfaces; compatibility with this machine's Declawd wrapper still requires the separate live terminal check. Do not adopt unrelated claims from search summaries.

`buildLaunchConfig({workspace,roomId,name,hubUrl,context='',sessionFile,resume=false,command='codex'},{nodePath=process.execPath,adapterPath=<absolute src/mcp/main.js>}={})` in src/runtime/launch-config.js returns `{command,args,cwd}`. It validates a real workspace directory, nonempty room ID/name, an HTTP root URL on loopback or a private LAN IPv4 address, supported resume/file combination, and nonempty executable path/name. Resolve workspace/session/adapter paths absolutely, never infer the code repo from launcher cwd. Reject malformed/unknown options early. Use buildParticipationInstructions for the final prompt.

Build an argument vector with one `-c mcp_servers.agent_chat_room={...}` inline TOML table containing `command`, `args`, `env` (`ROOM_HUB_URL`, `ROOM_AGENT_NAME`, `ROOM_WORKSPACE`, `ROOM_CONTEXT`, optional session-file/resume), `startup_timeout_sec=30`, `tool_timeout_sec=30`, and `required=true`, followed by the compact bootstrap prompt. Set the spawned process's cwd to the selected workspace. Node executable and adapter path are absolute. TOML basic strings/arrays must preserve literal values (JSON string encoding is compatible for well-formed strings); do not use JSON object syntax for TOML inline tables. No shell concatenation/interpolation, no writes to client configuration, no permission overrides.

scripts/chat.js accepts `--workspace` (default cwd), required `--room`, `--name` (default Agent), `--hub` (default loopback8787), `--context`, optional `--session-file`, `--resume`, `--command` (default codex), and `--help`. Explicit `--command declawd` (including a path with that basename) prefixes `--codex` and retains startup diagnostics. Spawn config.command with args, cwd and inherited stdio, shell:false. Propagate exit code/signals and handle launch errors concisely. `--help` must not launch a client. No arbitrary pass-through client options. Existing scripts/codex.js remains untouched.

A2.1 writes scripts/chat.js, src/runtime/launch-config.js, test/runtime-a2-1.test.js. Test using a fake child that records only intended arguments/cwd: separate code/workspace locations, quotes/newlines/backticks/$() retained literally, prompt builder usage, configuration values, invalid inputs/help, nonzero child exit and cleanup. Do not launch an authenticated model in automated tests.

LAN extension: `scripts/chat.js --invite` prompts for an agent invitation code. The MCP configuration includes `env_vars=["ROOM_INVITE_TOKEN"]` to forward it without placing the value in argv. The adapter accepts that variable for enrollment; new session files include `hubUrl` and reject resume to another origin. Existing loopback-only wording in the original A1.5 design above is superseded by the [LAN contract](lan-v1.md).

Claude workspace selection: `prepareAdapterConfig` chooses `ROOM_WORKSPACE`, then the client-provided `CLAUDE_PROJECT_DIR`, then the adapter process's current directory for a new participant. Claude's user-scoped MCP configuration can omit a fixed workspace. On resume, either explicit or client-provided workspace selection must resolve to the saved workspace; a mismatch returns `WORKSPACE_MISMATCH` without rewriting the session file. An explicit override continues to take precedence. SDK subprocess tests verify distinct project attribution and identities, while configuration tests cover override precedence, invalid directories, equivalent paths and resume mismatches. See the [Claude setup guide](../setup-another-machine.md#claude-code); real Claude client behavior remains a live acceptance check.

## Conversational enrollment

`join_room` accepts `{room_id, hub_url?, invite_token?}`. `invite_token` may be null to explicitly omit a configured invitation. The MCP initialize/list-tools path makes no hub requests and writes no session file. `join_room` selects the hub and invitation before calling the existing authenticated room join API; connection options never enter the room-join HTTP body. `list_rooms` connects using the current selection or environment defaults.

`hub-session.js` serializes connection selection and caches a connection across calls. Explicit join input overrides defaults, and omitted input keeps the current selection. Default invitations are scoped to the normalized default hub origin; hub overrides cannot forward them elsewhere. All URL validation and hub access checks remain in effect. Known enrollment/configuration errors use fixed local messages so server errors do not echo invitation values; failed joins do not disable the MCP. An existing valid connection is retained when selection validation fails.

Changing hub or invitation while in a room returns ACTIVE_ROOM_CONFLICT. After leaving, an adapter without a session file may select a new identity with a fresh resume secret. A saved session cannot switch hubs or change an enrolled identity's invitation. A definitively rejected invitation can be corrected before successful enrollment without rewriting that session file. Uncertain issuance is retained across same-input retries. Invitations are never written into session files or returned in tool data, but the terminal client may retain user-provided tool inputs or conversation text.

Actual SDK subprocess tests cover idle initialization, delayed hub startup, invitation correction and reuse, room access enforcement, two-way messaging, hub changes, credential isolation, saved-session resume, and cancellation. Native Codex/Claude under Declawd remains a manual acceptance check.
