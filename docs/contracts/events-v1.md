# Durable event and batch methods, local v1

Design interfaces for H1.3/H1.4. Implement against actual H1.1/H1.2. Factories use the existing synchronous database wrapper, identity/room stores and mutation journal. Validate direct inputs with shared schemas. Return public shared shapes, generic typed errors, never SQLite rows/secrets. Mutations own their transaction; route callers must not wrap `post` in an additional transaction because notifications occur after its commit.

## H1.3

`createEventStore(database,{identity,rooms,now=()=>new Date().toISOString(),id=crypto.randomUUID,onChange=()=>{}})` returns:

- `post(context,roomId,input)` -> RoomEvent. Parse Inputs.postMessage, require current active membership inside the transaction, use journal key operation `postMessage` and normalized input/room. Same request replays the original event without appending/notifying; conflicting input fails. A reply parent must exist in the same room or give VALIDATION_ERROR. Snapshot author from authoritative current Participant. Allocate room sequence, append and store the request outcome atomically. Refuse unsafe sequence overflow. Invoke onChange(roomId) only after successful new commit; a notification failure must not turn a committed post into an ambiguous failure (notifications are hints, durable reads are authoritative).
- `history(context,roomId,{before,limit=50,through}={})` -> History. Active membership is required. Snapshot head in the read transaction; optional `through` is an internal nonnegative safe integer ≤ current head used to assemble a join snapshot. Report that cutoff as head_sequence. `before` is exclusive and a safe nonnegative integer; page size 1–100. Return newest matching page sorted ascending. `next_before` is its first event sequence only when an older matching event exists; otherwise null.
- `head(context,roomId)` -> current safe head integer after membership check.
- `after(context,roomId,{after,limit=100,through}={})` -> `{events,head_sequence}`. Active membership; after is a nonnegative safe integer no greater than the selected head; same internal through cutoff as history. Return ascending first limit raw events greater than after, including author's own posts. No filtering, waiting, acknowledgement or browser state.

Use per-room uniqueness and journal guarantees already defined; no additional migration. H1.3 writes only src/hub/event-store.js and test/hub-h1-3.test.js. Tests cover ordered appends, two independent connections to one file, normalized duplicate/conflicting retries, multiple replies/same-room enforcement, author snapshot, room isolation, ascending pagination/bounded join history, stale generation and notifications after commit. Verify focused tests plus actual H1.2 suite.

## H1.4

`createDeliveryStore(database,{identity,rooms,events,now=()=>new Date().toISOString(),id=crypto.randomUUID})` returns:

- `receive(context,roomId,{limit=50}={})` -> ReceiveResult immediately, never a promise/timer. Require an agent and current active membership inside one transaction. Replay an existing pending batch exactly (regardless of a new requested limit). Otherwise scan the first limit raw events after acknowledged_sequence. No raw events -> timeout with unchanged acknowledgement and no batch. Raw events -> persist one batch containing all non-self visible messages and scanned_through at the last raw event. Return batch even when visible events are empty. Filter only by author.id; no knowledge/read inference. A paused membership returns timeout without new progress (a pending batch still replays).
- `ack(context,roomId,input)` -> AckResult. Parse Inputs.ack; require agent/current context and the supplied active epoch before consulting the journal (operation `ackEvents`). Reject unknown/foreign/invalidated/old-epoch batches with INVALID_ACK or MEMBERSHIP_ENDED as appropriate. For the matching pending batch, atomically advance acknowledgement, mark acked and record outcome. Repeating the same successful request returns its original outcome. A new request ID acknowledging the same already-acked batch in the same active epoch also returns the batch's original scanned position, without reducing the current cursor. Different inputs under a used request ID yield IDEMPOTENCY_CONFLICT. No arbitrary sequence acknowledgement.

H1.2 leave already invalidates pending rows; do not rewrite room-store. Retain historical acked/invalidated batches. New connection generations may process retained batches; old connections cannot. H1.4 writes src/hub/delivery-store.js and test/hub-h1-4.test.js. Test independent progress, exact pending replay/reopen, filtered empty batch, invalid/foreign/old epoch ack, cumulative monotonic progress and generation replacement. No HTTP/waiters/notification ownership in this packet.
